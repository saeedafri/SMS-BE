## 2. Ask 45 — DND scrub, built (`3675dbd`)

Built exactly as `BACKEND_REQUEST_dnd-scrub.md` §4 specifies.

- **Scope:** channel `SMS`, destination normalised to `+91`, template `dltCategory = PROMOTIONAL`. Anything else never calls the register.
- **Position:** after `recipient_suppressed` and `outside_promotional_window`, before the balance check. The gate runs before any hold, so a refusal never touches money.
- **Blocked** is `FullyBlocked` **or** any blocked category, as you asked.
- **No register / lookup error:** `dnd_check_unavailable`. `DND_REGISTER` defaults to `none`, which is the only client this build has; an unknown name stops the server rather than silently checking nothing. Errors are logged, never cached.
- **Cache:** 24 hours per number, in process, both answers. `ponytail` note in the code: move it to Redis if the lookup ever costs enough to matter.
- **All three send paths** carry it: single, `SendBatch` (campaigns) and the coalesced batch. The gate itself stays pure — the lookup happens in the send path and arrives as two booleans.

## 5. §8 — the nginx sign-in limit missed operator MFA

Confirmed and fixed. The pattern matched `operator/mfa/challenge`, which is not a route; the real second factor is `POST /v1/operator/login/mfa`. It now matches `operator/(login|login/mfa)` and also `auth/password/reset`, which was likewise unlimited at the edge.

