- **2.1** `DeliveryReport.Carrier` is set in `handle`. `FindMessageByCarrierRef` matches `carrier = ? AND carrier_ref = ?`, and the other-base fallback is kept under the same scope. RCS webhooks pass an empty carrier (any): their references are ids the vendor issues.

- **2.8** One rule, `outcomeOf`, is used by `service.go`, `coalesce.go` and `batch.go`. `NO_OPERATOR_BIND` and `DLT_IDS_MISSING` become `rejected` with the lowercase code, no error class and cost 0.
- **2.6** Every reload writes health from `bind.Health()`: `bound` with `lastBoundAt`, or `error` with the last error. It writes `unbound` for binds it closed. The console test reports a live bind's health instead of opening a second session under its `system_id` (from "Smaller").
- **2.7** Connects use a 10 s dialer. `ProbeSMPP(ctx, …)` ends when the request does, and `Sync` dials in parallel.
- **2.5** `carrier -> []*SMPPBind`, round robin. Each bind keeps its own TPS and window.
- **2.9** The error class comes from `stat`, and `OccurredAt` from `done date`. **Receipt dates are read as IST**: SMPP 3.4 dates carry no zone, and every operator this binds to is Indian.
- **2.2** A written, unanswered submit (`SUBMIT_TIMEOUT`) is `submitted` with its hold kept. The waiter is not dropped, so a late `submit_sm_resp` settles it through `LateSubmit`. A wait that ends before writing produces **no receipt**: the message stays `queued` with its hold and is sent when the bind has room. If it can never be sent (bind closed, window passed), it is refused `no_operator_bind` at cost 0. Bulk gets one tick in every **5** while priority traffic waits. The `windowSize: 1` edge is documented in the code.
- **Smaller, segment counts.** The test found a real mismatch: the library split 160 GSM-7 characters into 2 segments (billed 1), and 81 `€` into 1 (billed 2). `billing.Segments` is now the single split, used both by billing and on the wire.

- **`776ef5e`** reverses one choice in `9dc8b78`. Letting the reconciler expire `queued` rows made rows for deleted tenants fill its page ahead of real messages. That happened in `sms_test`, and would in production for any deleted tenant. The "never sendable" path above replaces it.
